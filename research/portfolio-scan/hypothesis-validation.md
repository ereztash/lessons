# Hypothesis Validation at n=25

> Cross-repo hypotheses originally formulated at n=4 (cor-sys, groundstate-protocol,
> chess-mind-patterns, core-unified-consciousness). Validated here at n=25 (full portfolio).
> Source data: `/research/portfolio-scan/26-repos.md`.

---

## Original hypotheses (H1–H5)

### H1: 4-feature Tier classifier cleanly partitions repos

**Original verdict (n=4)**: Confirmed — lower-bound on system-mode commitment.  
**n=25 verdict**: **CONFIRMED WITH EXTENSION**

The classifier partitions cleanly within the software subset. However, **36% of the portfolio (9/25 repos) is non-software**: empty repos, document dumps, and script collections that score 0–1/4 for structural reasons unrelated to software maturity. These need a **Tier D pre-filter** before applying the 4-feature score.

Refined classifier at n=25:

```
Pre-filter: Is this a software project? (runnable code + intentional structure)
  → No  → Tier D (knowledge, empty, script-dump)
  → Yes → Apply 4-feature score
      0/4 → Tier C (Lovable-only abandoned)
      1-2/4 → Tier B (resumed prototype)
      3-4/4 → Tier A (managed system)
```

Key finding: Only **one true Tier C** at n=25 (core-unified-consciousness). Prior session predicted more Lovable-abandoned repos, but most Lovable projects in the portfolio were resumed (chess-mind-patterns, brain-healer-hub, org-fortify, groundstate-protocol) — not abandoned. The Tier C failure mode is rarer than the empty-repo failure mode.

**Confidence in classifier**: High. Score distributions are cleanly separated. No repo falls ambiguously between Tier A and Tier B on the full feature count.

### H2: Publish-button satisfiability predicts abandonment

**Original verdict (n=4)**: Confirmed — strongest single predictor.  
**n=25 verdict**: **CONFIRMED + ONE REFUTING CASE**

The H2 signal holds across the expanded dataset:
- All Lovable-bootstrapped repos with Supabase/real-API backends are Tier B or above (brain-healer-hub, org-fortify, groundstate-protocol, ampaign-craft)
- The one Tier C repo (core-unified-consciousness) has zero backend deps and zero non-template production dependencies
- Algo-trade and CandiApp (dormant Tier A) have complex success conditions (live IBKR trading, production HR API) that couldn't be satisfied by any publish button

**One partial refutation** (keepath): keepath has a success condition that absolutely cannot be satisfied by a publish button (requires PostgreSQL, NestJS API, 4 Next.js apps, AI engine). Yet the repo is dormant (133 days, operator-absent). This means H2 is necessary but not sufficient for resumption. A non-trivially-satisfiable success condition is required for resumption, but does not guarantee it if the operator is overwhelmed by the blast output.

**Refined H2**: Publish-button satisfiability predicts *abandonment risk*. Non-satisfiability predicts *resumption precondition* — but resumption still requires operator engagement. The operator-absent pattern (keepath) is a new failure mode: build too large for operator to pick up.

### H3: Anti-pattern-as-permanent-memory habit drives health

**Original verdict (n=4)**: Refined — the causal variable is the habit, not the LOG.md file format.  
**n=25 verdict**: **REFINED FURTHER**

New finding: org-fortify has a LOG.md file but all commits are Lovable-bot. The LOG.md was almost certainly generated by a Lovable prompt ("add a LOG.md") rather than authored by the human operator as a commitment device. This **weakens the LOG.md as a signal** for the anti-pattern memory habit.

At n=25, the habit is clearly present only in:
- COR-SYS: human-authored LOG.md + explicit anti-pattern table that grew over time
- groundstate-protocol: distributed anti-pattern memory in Hebrew PR templates
- ampaign-craft: CLAUDE.md + comprehensive docs/ (ACCESSIBILITY.md, SECURITY.md, CHOICES.md, CONTRIBUTING.md)

The revised signal: **human-authored documentation infrastructure** (not bot-generated file presence) predicts the anti-pattern memory habit. A LOG.md created by a bot prompt is not the same artifact as one created by an operator encoding friction.

**Confidence in H3 refined**: High.

### H4: AI tool diversity predicts maturity (Tier)

**Original verdict (n=4)**: Confirmed — monotonic with tier.  
**n=25 verdict**: **CONFIRMED**

| Tier | Typical AI tool count | Tools observed |
|------|-----------------------|----------------|
| A | 2–4 | Lovable + Claude Code + Codex (groundstate); Claude Code + Cursor (COR-SYS); Lovable + Claude Code (ampaign-craft) |
| B | 1–2 | Lovable + Claude Code (brain-healer-hub, chess-mind-patterns); Claude Code only (kolzchut, keepath) |
| C | 1 | Lovable only (core-unified-consciousness) |
| D | 0–1 | None or ereztash's own commits only |

Monotonic relationship holds. New insight: **two Claude Code-only Tier A repos** (Algo-trade, CandiApp, lessons) show that multi-AI diversity is a sufficient but not necessary condition for Tier A. High depth of use within a single tool (Claude Code + PRs + docs) can substitute for breadth.

### H5: Editorial voice escalation predicts health

**Original verdict (n=4)**: Confirmed for directionality; usable as follow-up health check.  
**n=25 verdict**: **CONFIRMED + EXTENDED**

New top-of-escalation observation: ampaign-craft's most recent commits show research-citation voice at par with groundstate-protocol's most advanced commits (citing calibration methodology, contamination disclosure handling, 10 open uncertainties). This is now the second confirmed repo showing research-citation escalation.

New bottom-of-escalation observation: The Tier D repos show commit voices that never escalated beyond upload-batch level — "Add files via upload", "Initial commit", 7-byte README. Editorial escalation doesn't start without a baseline of structured commits.

**New finding**: Repos where Claude is the commit author from day one (keepath, brain-healer-hub Claude commits) show **high editorial voice in Claude's commits but zero operator editorial voice**. The operator's merge commits are blank ("Merge pull request #5…"). This means the editorial voice signal applies to the *repo's commit history as a whole*, not just to Claude's commits — and an operator with no editorial voice in their own commits is at risk of the keepath pattern regardless of Claude's voice quality.

## New hypotheses (H6–H8) — surfaced at n=25

### H6: Claude-batch repos are a distinct failure mode

**Statement**: A repo built by Claude in a single large-scale batch (>2 Claude commits creating the majority of the codebase) with no operator commits after the batch will not be resumed unless the operator actively re-enters the codebase within 72 hours.

**Evidence**: keepath — 2 Claude commits (2025-12-30, 2025-12-31) building a complete 4-app + NestJS + AI monorepo. Default branch never merged to main. No operator commits. Dormant 133 days. The batch was *too large to pick up*: 27 API endpoints, Turborepo, 4 apps, Docker, CI/CD, Prisma schema — the operator faced a complexity cliff on resumption.

**Contrast**: groundstate-protocol — Claude batches are bounded by sprint-shaped branches (claude/* branch per PR). Each sprint is a digestible unit. Operator can resume after any sprint. The sprint-container pattern is the anti-batch pattern.

**Confidence**: Low (1 observed case). Needs 2nd repo to promote.

**Implication for SaaS scanner**: Flag repos where Claude commit count > 80% of total commits AND no operator commits after the batch. Offer "resumption scaffolding" intervention.

---

### H7: Tier D repos are not recoverable via the existing playbooks

**Statement**: Tier D repos (non-software, empty) are not the target audience for any existing playbook. They represent conceptual experiments, document storage, and file dumps — categories where the operator never intended to build runnable software.

**Evidence at n=25**: 9/25 repos are Tier D. They divide into:
- **Empty placeholders** (Focuos, Masse-agent, onto-trade, Resilience_calculator, pilot): 5 repos. Created and immediately abandoned — the repo itself was the artifact (a name claim or a placeholder for future intent).
- **Document/knowledge repos** (Hr_SMB, Contradiction_loss): 2 repos. GitHub used as a Dropbox or Drive substitute. No software intent.
- **Script dumps** (Metatrader, nuxtjs-boilerplate): 2 repos. Pre-Claude-Code exploratory scripts uploaded without structure.

**Implication**: The Tier D category is invisible to all existing playbooks (publish-button triage, four-feature classifier, resumer-day-prep). A scanner surfacing Tier D repos should classify them as "out of scope" rather than "abandoned" — the operator had no resumption intent.

**Confidence**: High (9 consistent observations). Ready to extend the four-feature-tier-classifier playbook with the Tier D pre-filter.

---

### H8: Age predicts dormancy more reliably than any single feature

**Statement**: The most reliable predictor of a repo being dormant (days-since-commit > 90) is its age (creation date). Repos created before 2026-01 are statistically more likely to be Tier D or dormant Tier B than repos created after.

**Evidence**:
- Created ≥2026-01: ampaign-craft (2d ago), groundstate-protocol (6d ago), brain-healer-hub (39d ago), chess-mind-patterns (50d ago), kolzchut (52d ago), COR-SYS (33d ago), core-unified-consciousness (64d ago), org-fortify (46d ago), All_Erez-s_Connections (41d ago), lessons (0d ago) — 9/10 are active (≤90d). 1 exception: core-unified-consciousness (64d).
- Created <2026-01: keepath (133d), nextjs-ai-chatbot (261d), Organziational_algo (184d), Algo-trade (176d), CandiApp (174d), Benchmark.ATS (175d), Hr_SMB (166d), pilot (120d), Resilience_calculator (146d), Focuos (242d), Masse-agent (322d), onto-trade (295d), Contradiction_loss (183d), Metatrader (344d), nuxtjs-boilerplate (407d) — 15/15 are dormant (>90d).

**Finding: 100% of pre-2026 repos are dormant.** This is a perfect age-activity split in the dataset. The portfolio underwent a qualitative shift around 2026-01 — likely the adoption of Claude Code + Lovable as primary tools.

**Caveat**: This is a single operator's portfolio over ~14 months. The age correlation may reflect tool adoption timing rather than a generalizable law. Needs cross-operator validation.

**Confidence**: High within this dataset. Confidence in generalizability: Low.

## Implications for SaaS spec

1. **Target audience is narrower than expected**: Only 15/25 repos are software projects (Tier A/B/C). The scanner should immediately identify Tier D repos and exclude them from active recommendations.

2. **Tier A dormancy is a real segment**: 2 of 6 Tier A repos (Algo-trade, CandiApp) are dormant 174-176 days. These are *the most valuable resumption targets* — fully built systems waiting to be restarted. The playbook value for these is higher than for Tier B.

3. **The keepath intervention**: A new product feature — "blast detection" — identifies Claude-batch repos that were never picked up and offers a guided re-entry prompt.

4. **The publish-button pre-screen** (H2) is the highest-ROI insight to encode in the scanner UI: show the operator whether their Lovable project's success condition requires leaving the platform.

5. **Hebrew market signal**: 9/25 repos have Hebrew content. The operator's primary language is Hebrew. The SaaS product should be bilingual HE+EN from day one, or at minimum use English UI that doesn't confuse Hebrew content (RTL-safe displays).
