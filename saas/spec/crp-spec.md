# Context Repository Protocol (CRP) — Formal Specification v0.1

## What is a CRP?

A CRP is a git repository structured so that an AI coding assistant (specifically Claude Code)
can bootstrap a working session context in under 3,000 tokens, without requiring the human
operator to explain the project from scratch.

The core claim: a CRP is not a documentation repo, and not a knowledge base. It is a
**machine-consumable context provider** — a repo where the file layout itself is the API,
and a defined bootstrap sequence (Gate 0) is the connection protocol.

---

## Required elements

A repository is CRP-compliant only if ALL of the following are present:

### R1 — Gate 0 entry point

A file named exactly `CLAUDE.md` must exist at the repository root.

It must contain a section whose heading includes the text "Gate 0" (case-insensitive).

The Gate 0 section must specify a read order — a list of files to read at session start,
with the purpose of each.

Rationale: without an explicit bootstrap sequence, an AI assistant has no deterministic
starting point. A file named CLAUDE.md with no Gate 0 is documentation, not protocol.

### R2 — Machine-queryable index

A file must exist at exactly `research/repo-index.md`.

It must contain at least 3 entries, where each entry is introduced by a level-2 Markdown
heading (`## entry-name`). The heading text must be a noun (typically a project, repo, or
domain name), not a section title like "Overview" or "Introduction".

Each entry should contain, at minimum: a tier or status classification, and 1-3 key
findings or notes relevant to that entry.

Rationale: the index must be queryable by name in a single grep. If the file requires
sequential reading to find a specific entry, it fails the machine-queryable requirement.

### R3 — Session protocols

A directory named `pipelines/` must exist at the repository root.

It must contain at least one Markdown file describing a session protocol — a step-by-step
sequence of actions for Claude Code to follow in a specific scenario.

At least one of those files must be named `dual-repo-session.md` and must describe
a protocol for when Claude Code has access to this repo AND a second target repo
simultaneously.

Rationale: protocols turn documented conventions into executable workflows.

### R4 — Reusable behaviors

A directory at `.claude/skills/` must exist and must contain at least one Markdown file.

Each file in this directory defines a named skill — a reusable behavior that Claude Code
can invoke by name.

Rationale: skills are the executable unit of knowledge in a CRP. Without them, the repo
is a read-only reference, not an active context provider.

---

## Optional elements (warnings if absent)

These do not disqualify a repo from CRP compliance, but their absence reduces quality:

### W1 — State persistence

A file named `MEMORY.md` should exist at the repository root, containing a summary of
current project state. Its absence means state is not persisted across sessions.

### W2 — Enforcement spine

A file named `LOG.md` should exist at the repository root.

If present, it should appear human-authored: it must contain domain-specific sections
(not just a generic changelog), and must reference concrete artifacts (files, commits,
counts). A LOG.md that could have been generated by an LLM prompt — with only generic
section headings like "Updates" or "Changes" — does not satisfy this criterion.

### W3 — Self-compilation

A directory at `saas/app/scripts/genesis/domains/` (or equivalent) may contain typed
fixture files representing domain knowledge that a code-generation pipeline can consume.

If any such fixture exists whose filename (without extension) matches the repository's
own name, the repo has compiled itself — evidence that the CRP's tooling has been
self-applied.

---

## What CRP is NOT

- A CRP is not a README or documentation site. Documentation exists for humans to read.
  A CRP exists for Claude Code to bootstrap.
- A CRP is not a skill file. A single skill file describes one reusable behavior.
  A CRP is an entire repo whose structure defines a session interface.
- A CRP is not a RAG knowledge base. RAG requires an indexing pipeline and query API.
  A CRP uses structured file layout and naming conventions — no runtime infrastructure.

---

## Compliance scoring

A repo passes CRP compliance if and only if all 4 required elements (R1–R4) are satisfied.
Each unsatisfied required element is an error. Each unsatisfied optional element is a warning.
A compliant repo may have any number of warnings.
